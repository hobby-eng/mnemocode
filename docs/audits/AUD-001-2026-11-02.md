## Review evidence

### Scope and methodology

A compact full-scope audit, not the expanded specialist workflow: the Rust workspace at the reviewed commit, that is the library `mnemocode`, the cards crate, the command line with its menu, the WebAssembly binding with its four page profiles, the release tooling, the workflows and every document. Environment: Linux 7.0 on x86-64, 16 threads, Rust 1.99.1, nightly for the fuzzer only, cargo-audit 0.22.2, wasm-bindgen 0.2.129, Docker 29.9.2, Node.js 26.12.1 for the reference program, Chrome 155.0.8059.79, Firefox 158.0. Methods: the repository's gates; a differential run against MnemoCode 0.1.0 with random damage; edge probes; bounded fuzzing; the page files in real browsers; the canonical container; every claim of the documents against code and runs, by a reviewer with its own computation of the manual recovery; a source trace of secrets, randomness and the network. Two review rounds and a follow-up came before this audit; their findings are in the commit record of b677647, and the audit took them as a regression list, not as its scope.

Excluded: The internals of upstream crates, the vendored SSKR crates included: their calls were reviewed, and their files compared with UPSTREAM.json. No browser interface, provider, transaction or discovery code exists in this repository. No cryptographic proof, and no certification, is implied.

### Findings

#### SEC — Secret lifecycle

##### AUD-001-SEC001 — Medium — Codes and records live in plain strings, against the design's owner types

- **Category:** SEC.
- **Severity:** medium.
- **Status:** verified.
- **Release blocking:** false.
- **Affected files and builds:** `crates/mnemocode/src/forms.rs:211`, `crates/mnemocode/src/backup.rs:257-264`, `crates/mnemocode/src/backup/json.rs:20`, `crates/mnemocode-cli/src/commands/encode.rs:132,536,552`, `SECURITY.md:41,43`, `README.md:280`, `docs/design/architect/ARCHITECTURE.md:295-296`.
- **Reproduction:** Read `Backup::text`, `Backup::record` and `Form::codes` at the reviewed commit: each returns a `String`. `encode --mode direct` writes the phrase itself in another form through them. `Date` is `Copy` without `Drop`, and `derive_shifts` returns a `Vec<u16>`.
- **Expected behavior:** RUST-13 and ARCHITECTURE.md's table: codes, the MNC1 record and JSON live in `EncodedBackup` and `SecretText`, wiped and locked where their size allows. SECURITY.md names drawn pages as the only memory left unlocked.
- **Observed behavior:** The codes and the record of a backup stood in unlocked `String`s for the rest of a command, with no redaction. Their heap blocks were wiped on free by the zeroing allocator. Stack copies of a `Date` are not wiped, and shift schedules are not locked; both are short-lived working values.
- **Impact:** Where swap is in use, these buffers were not kept out of it, while the documents said so. A debug print of the text would not have been redacted. No leak was demonstrated: the allocator wiped the blocks, and core dumps stay off.
- **Recommended fix:** Return `SecretText` from `Form::codes`, `Backup::text`, `Backup::record` and `json`, and keep the record line in one. Name a step's working copies as the exception in SECURITY.md, README.md and ARCHITECTURE.md.
- **Required verification:** A test that the codes and the record print as redacted; `cargo xtask check`, whose memory scan covers the entries that use them; a byte-equal differential run.

##### AUD-001-SEC002 — Medium — The menu's word lookup is called free of secrets, yet takes words of a phrase on the command line

- **Category:** SEC.
- **Severity:** medium.
- **Status:** verified.
- **Release blocking:** false.
- **Affected files and builds:** `crates/mnemocode-cli/src/menu/table.rs:41`, `crates/mnemocode-cli/src/os/child.rs:3`, `SECURITY.md:42`, `README.md:60`.
- **Reproduction:** On a pty: start the menu, choose 8, then 1, and type `abandon`. The alternate screen is not entered, the main screen keeps `Word: abandon` and `mnemocode table --word abandon`, and the child process has the word in its arguments.
- **Expected behavior:** SECURITY.md: the start menu holds no secret. README.md: enter recovery material on the private screen or through local files, never as command-line text.
- **Observed behavior:** The entry is labelled "Look up a seed word, its number or its Unicode code" and treats the word as public, as 0.1.0 does.
- **Impact:** A person who looks up the words of a real phrase one by one leaves them in the scrollback, and in `ps` while each child runs. It needs a person's use of the lookup for a real phrase; a single word alone is not the phrase.
- **Recommended fix:** Say so in SECURITY.md and README.md, and point to a saved word list for a real phrase. The behaviour stays that of 0.1.0 (RUST-14).
- **Required verification:** The documents read back against the menu's behaviour.

#### SEC — Local boundaries

##### AUD-001-SEC003 — Medium — Exported files are called private to the user where Windows keeps them open

- **Category:** SEC.
- **Severity:** medium.
- **Status:** verified.
- **Release blocking:** false.
- **Affected files and builds:** `SECURITY.md:47`, `crates/mnemocode-cli/src/os/files.rs:427-447`.
- **Reproduction:** Read `private_folder` and `private_file`: the modes 0700 and 0600 are set under `#[cfg(unix)]` only, and no code sets an ACL on Windows. Windows was not run.
- **Expected behavior:** SECURITY.md: exported files can be read only by your user account, where the system supports this.
- **Observed behavior:** NTFS supports per-user ACLs, and an exported file takes the ACL of its folder. On Linux the modes 600 and 700 were confirmed by the probes.
- **Impact:** On a shared Windows computer, a file saved into a folder that others can read can be read by them. 0.1.0 behaves the same and says so in its release notes.
- **Recommended fix:** State the limit in SECURITY.md: Linux and macOS, on file systems that keep Unix permissions; Windows takes the folder's permissions.
- **Required verification:** The document read back against the code.

#### SEC — Availability bounds

##### AUD-001-SEC004 — Low — The read of a QR image has no bound on its time, and Ctrl+C waits for it

- **Category:** SEC.
- **Severity:** low.
- **Status:** deferred.
- **Release blocking:** false.
- **Affected files and builds:** `crates/mnemocode/src/qr.rs:271-289`, `rqrr 0.11.0 src/prepare.rs:268-305`.
- **Reproduction:** `decode --qr-file noise.png` with a PNG of random pixels at 2896 x 2896 took 94 s in a release build. An image of the same size with its top 49.75% noise and the rest white was stopped after 240 s. Ctrl+C at 1.5 s gave no prompt after 20 s. Real page images read at once: 104 of 104 pages.
- **Expected behavior:** CORE-50: work that grows with input stops at a limit that the program states. The size limits of the image hold; time has none.
- **Observed behavior:** rqrr clones the whole image for each group of finder patterns it tests, and noise offers many. Its API gives no count of them and no way to stop. 0.1.0's reader takes 34 s on the same noise.
- **Impact:** A hostile or damaged image can keep one command busy for minutes or more, ignoring Ctrl+C; closing the terminal or SIGKILL ends it. No secret is touched, since the read happens before any result.
- **Recommended fix:** Not bounded yet. ### Informational observations and recommendations

- `encode --cards-dir X --page-size a4` shows the result and only then refuses the size, with exit 1. 0.1.0 does the same, byte for byte, so it is parity; refusing before the secret would be better in both programs.
- With `--ask-secrets` on a terminal that cannot run it, the terminal is named before the command's own options, where 0.1.0 names the option. Both refuse and show nothing secret. PLAN.md's parity list records it.
- The Docker build depends on snapshot.ubuntu.com, which failed with 502 and 503 for part of this audit. A release would wait for it.
- `fuzz/text` runs about 64 inputs a second under AddressSanitizer, since each input goes through every form and mode: its 19,378 runs are a light pass.
- Open questions of the port remain the owner's, as PLAN.md and the commit records list them; none is a defect of this snapshot.

### Assessment and limitations

No critical or high finding stands, and none of the 15 blocks a release. 14 are verified on their fix commits, and 1 Low finding is deferred with its reason. Within what ran, the Rust program gave the reference's results in every case, read and wrote its formats, kept its secrets out of errors and output, and built to the same bytes twice. This is the owner's record for the release decision, not a certification. Release acceptance stays open until the release workflow has run on the three systems, which needs a remote, as GATES.md requires.

- Windows ran only under Wine 9.0, and ARM64 only under qemu-user 8.2.2; macOS did not run at all. Their console, ACL, sandbox and Landlock paths are read or compiled, not run on those systems. ConPTY never ran.
- No workflow has ever run: the repository has no remote. The release workflow, the attestations, the signature steps and the two macOS builds are unproven.
- `cargo xtask reproducible` did not finish: downloads from static.rust-lang.org failed inside the container on every attempt. The toolchain layers were not rebuilt for the comparison.
- The reference program is one implementation of the same design, by the same project: agreement shows parity, not correctness against an independent oracle, beyond the published vectors.
- Fuzzing was bounded to 300 seconds a target, `text` at 64 inputs a second. Upstream crates were not fuzzed on their own.
- A real unencrypted swap area, a failed self-test in the menu, FAT and exFAT media and a real photograph of a QR code were not exercised.
- SEC004 stays deferred. The owner's open questions of the port remain as the commit record and PLAN.md list them.

Not performed: no push, tag, release or remote change; no change to the owner's settings; no real secret used; no paid runner dispatched.
