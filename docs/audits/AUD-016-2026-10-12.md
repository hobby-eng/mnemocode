### Findings

#### AUD-016-API001 — Medium — Wallet answer snapshots discard valid prototype getters

- **Category:** API
- **Status:** open
- **Release blocking:** true; Resolve the regression in the supported public WalletMatch contract before release.
- **Affected files:** `src/core/wallet-check.ts:54` (`ba1178543bf99849e7f4e5419a2c50381086036ffe97dbae9c68121453610bdf`)
- **Reproduction:** Call askWallet with a class whose prototype getters return matched:true and path:'m'. Also use an own matched:true field with path provided by a prototype getter.
- **Expected behavior:** Accept both structurally valid WalletMatch objects and retain their declared result fields, reading each once.
- **Observed behavior:** The class is refused as malformed; the second answer is accepted with its path silently omitted. Two independent probe cases fail.
- **Impact:** Supported library hosts can lose a successful wallet match or its evidence after the remediation's object-spread snapshot. Native CLI answers are ordinary own-property objects and were not shown to fail. No forged wallet or secret disclosure is demonstrated.
- **Evidence:** `AUD-016-evidence/aud016-residuals.log`, SHA-256 `cad65cd646ebe735501dfe8e57508ab78717860c1903a088e057055f65649c5d` (local only).
- **Recommended fix:** Snapshot the declared WalletMatch fields by reading each once; preserve generic host result fields according to their contract. Do not assume supported fields are enumerable own properties.
- **Required verification:** Class/prototype and non-enumerable result fields must work; keep changing-getter snapshot controls and rejection of malformed matched values.

#### AUD-015-API001 — Low — Listed-code results still return after cancellation during fingerprinting

- **Category:** API
- **Status:** open
- **Release blocking:** false; Limited cancellation or best-effort cleanup gap; no direct secret compromise shown.
- **Affected files:** `src/core/missing-codes-search.ts:472` (`e411ec446317230f12e82aa6a6483d30cbb7aa457b42a09256d8deb42b18bac3`)
- **Reproduction:** Read '2027 10 2? 2027 10 24 2027 10 24 2027 10 377' as indexes/Seedshift and list candidates for 23-09-2026. Its fingerprint callback aborts the signal with Error('public list stop') and returns '00000000'.
- **Expected behavior:** Under the strengthened no-late-publication promise, reject with the same abort reason before returning the list.
- **Observed behavior:** ListWay.run returns kind:'list' while the signal is already aborted. The shared guard runs inside searched, before the later fingerprint awaits.
- **Impact:** A stopped library/browser recovery can publish a late candidate list. The original wallet-based AUD-015 reproductions now pass; this is another continuation of the same cancellation root cause. No wrong wallet or native secret leak is shown.
- **Evidence:** `AUD-016-evidence/aud016-residuals.log`, SHA-256 `cad65cd646ebe735501dfe8e57508ab78717860c1903a088e057055f65649c5d` (local only).
- **Recommended fix:** Call the existing shared assertStillRunning after the awaited fingerprint and before list publication/final return; do not add a separate cancellation policy.
- **Required verification:** Abort inside an asynchronous fingerprint must reject with its reason, while ordinary list and wallet searches continue to work.

#### AUD-015-SEC001 — Low — Throwing transport mappers leave partially populated arrays unwiped

- **Category:** SEC
- **Status:** open
- **Release blocking:** false; Limited cancellation or best-effort cleanup gap; no direct secret compromise shown.
- **Affected files:** `src/sskr/transport.ts:165` (`93c273cab4aefa4d702a0be4007b43f65baa4b934f3db2eb07a1299f7069c262`); `src/sskr/transport.ts:234` (`93c273cab4aefa4d702a0be4007b43f65baa4b934f3db2eb07a1299f7069c262`)
- **Reproduction:** Replace the last minimal Bytewords pair of a published UR share with 'zz', or its last full Byteword with 'zzzz'. Capture allocations by applying the original Uint8Array.from with a capturing Uint8Array subclass as its constructor.
- **Expected behavior:** Refuse the unknown token and wipe internally owned decoded bytes, including partial allocations created before a mapper throws.
- **Observed behavior:** Both readers refuse correctly, but each captured partial allocation still contains nonzero decoded share bytes. The mapper throws before from returns an array to the caller's cleanup wrapper.
- **Impact:** The ordinary successful-read and invalid-metadata buffers are now wiped; malformed-token failures retain an internal decoded prefix. This is a best-effort secret-lifecycle gap, not proof of heap-wide erasure failure or attacker access to process memory. Caller-owned valid output must stay usable.
- **Evidence:** `AUD-016-evidence/aud016-residuals.log`, SHA-256 `cad65cd646ebe735501dfe8e57508ab78717860c1903a088e057055f65649c5d` (local only).
- **Recommended fix:** Use an owned allocation with explicit decoding and a finally cleanup on failure, or validate all tokens before allocating; retain the common reader rules and successful-output ownership.
- **Required verification:** Unknown first/middle/last UR pairs and full Bytewords must refuse with captured arrays zeroed. Keep CRC/metadata failures, known-answer success and caller-owned-output controls.
