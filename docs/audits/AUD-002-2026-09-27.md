### Test and vector sufficiency

The suite is substantial for core arithmetic and SSKR transport, and the audit probes confirm the exported artifacts, but it is not yet a complete release gate.

- **Independent oracles:** 744 exhaustive entropy-tail cases (5 lengths × 3 schedules) computed with an in-test BIP39 construction; the published Seedshift example; the BIP39Colors 12-word vector; the official BCR-2020-011 SSKR vector with all 30 minimal quorums and independently computed RGB bytes; both word-list SHA-256 digests; the zero-entropy master fingerprint.
- **Same-implementation regressions:** seven MnemoCode public vectors (only `direct-12` carries fingerprints, unchanged since AUD-001); five deterministic SSKR fixtures from the pinned bridge; 120 production threshold policies; representation round trips for every length, format and mode.
- **Contract and negative coverage:** invalid words, checksums, lookalike glyphs, alternate number syntax, malformed records, damaged catalogue, damaged pinned digest, alias overwrite, symlink replacement, corrupted/truncated/reordered/mixed SSKR records, recomputed-CRC metadata corruption, 16-of-16, hidden-input failures, secret redaction.
- **Audit-added evidence (not in the suite):** 128 render matrix, 5 decoded QR member cards, 10 decoded PNG pages, 50 decoded fragments, uppercase/mixed/wrong-network/typo evidence, xpub/WIF/fingerprint evidence, input-limit files, crafted PNG headers, threshold bounds, 9 999-date recovery.

**Gaps:**

- No test exercises the 1 MiB, 16 MiB, 4096 px or 16 Mpx limits, and share/WIF/passphrase files have no limit (SEC001).
- The only Bitcoin evidence tests use BIP84 mainnet at index 0; BIP44/49/86, testnet, non-zero account/branch/index, WIF and xpub paths are covered by audit probes only.
- Checksum-valid Seedshift vectors 15–24 words still lack fingerprints; a second independent implementation of the entropy-tail shift beyond the in-test oracle does not exist.
- Rasterised QR readability of every template/size combination is checked only for the glass-6in1 QR cards, business-it fragments and the business/material A6 self-test renders; physical print and camera tests were not performed.
- Failure injection (RNG unavailable, interrupted writes, renderer timeout, full disk) remains unexecuted.

### Code quality and human readability

The code reads well. The module split described in `docs/ARCHITECTURE.md` matches the tree: a 43-line `core.ts` facade over seven transformation modules, a CLI layer that owns input, validation, reporting and export separately, an SSKR layer that separates runtime, shares, transport and self-test, and per-family renderers with layout and artwork modules. Comments are sparse (130 comment lines in 7 819) and almost all explain an invariant or unit: the entropy-tail modulus, the BIP39Colors decimal wire format, the Private Use Area radix, top-origin PDF coordinates, cache ownership, fragment-only QR payloads. Error messages are specific and never echo mnemonic tokens. Prettier passes with a 100-column width; 64 lines exceed it only where the formatter allows (long strings and template literals).

TypeScript 7.0.2 compiles with no diagnostics. The five `let … | undefined` patterns (lazy WASM engine, lazy renderer probe, lazy artwork, prompted dates, random buffer) are all read through the same variable that was assigned, so none has the narrowing problem found in the sibling project.

Measured hotspots (prompts, not defects): `printUsage` 316 lines of help text; `main` 144 lines of option allowlists; `runPreview` 100; `drawMaterialFront` 86; `runRecoverDate` 84; `printEncodeResult` 83. Non-null assertions: 77 (17 in `core/seedshift.ts`, 16 in `sskr/transport.ts`). Nested ternaries: 11, concentrated in HSV/RGB conversion and page-dimension tables. Concrete duplication is listed in AUD-002-ARC001.

#### AUD-002-ARC001 — Readability is good; geometry, colour and content-validation helpers are duplicated

The module boundaries hold and the code is comfortable to read. The remaining friction is repetition rather than complexity:

- `MM = 72 / 25.4` is defined in `export/business-layout.ts`, `export/material-cards.ts` and `export/glass-cards.ts`.
- The page-dimension table (`[210, 297]`, `[148, 105]`, `[85.6, 54]`, `[90, 50]` plus orientation swap) appears in `export/material-layout.ts:15-25`, `export/business-cards.ts:465-477` and `export/glass-layout.ts:27-40`, each as a nested ternary.
- `hsv()` exists in `export/business-artwork.ts:46` and `export/glass-artwork.ts:6`; `rgb()` in `glass-artwork.ts:14` is inlined again inside `businessArtwork`.
- `validateContent` (share/collection payload consistency) is repeated in `business-cards.ts:38-56`, `glass-cards.ts:53-68` and `material-cards.ts:95-109` with slightly different messages.
- Two `fit()` text-fitting helpers (`business-render-primitives.ts:19`, `glass-cards.ts:79`) differ only in minimum size and message.
- `src/color-export.ts:5` imports `cli/qr-export.ts`; the QR PNG writer belongs with the export layer.

**Recommendation:** one `export/page-geometry.ts` (sizes, orientation, `MM`), one `export/color-space.ts` (HSV/RGB), one `export/card-content.ts` (`validateContent`), and move `qr-export.ts` under `export/`. Keep the family renderers otherwise as they are; do not split `printUsage`.

**Verification:** `pnpm check`, `pnpm format:check` and the render matrix unchanged; `scripts/compare-business-goldens.py` shows identical pixels for the fixtures.

#### AUD-002-BLD003 — Canonical SSKR WASM rebuild is byte-identical; host builds differ; platform matrix remains

Building `vendor/sskr/rust` (identical source, lockfile and manifest hashes to the sibling repository's `packages/recovery-sskr-wasm`) inside the pinned reproducible container and running the repository's own `build-recovery-sskr-wasm.mjs` with networking disabled produced `recovery_sskr_wasm_bg.wasm`, `.js` and both `.d.ts` files byte-identical to the committed ones. The same build on this host (clang 21.1.8 instead of the container's 18.1.3, used by `secp256k1-sys` through the `cc` crate) yields a functionally equivalent binary with a different code section; the official vector and a zero-seed deterministic split give identical results with both binaries.

This closes the canonical-rebuild part of AUD-001-BLD002 for the SSKR module. It does not establish supply-chain provenance of the crates beyond `Cargo.lock` checksums, nor was Windows, macOS or any Node version other than 26.10.0 exercised.

**Recommendation:** Document the container rebuild as the only supported way to regenerate `vendor/sskr/generated`, and add a CI job on a second OS running `pnpm verify`.

#### AUD-002-SEC002 — Input budgets and secret lifecycle verified within stated limits

Text and stdin inputs stop at 1 MiB before decoding; PNG input stops at 16 MiB and at 4096 px or 16 Mpx before `pngjs` allocates. Entropy, random seeds, decoded WIF bytes, restored SSKR secrets and BIP32 nodes are cleared in `finally` blocks; exports are staged privately (0600/0700) and published atomically; hidden input refuses to run without a controlling terminal. Limits: JavaScript strings holding mnemonics, shares and WIF text cannot be erased; the `systemd-ask-password` dependency is Linux-specific; no allocation-failure or renderer-timeout injection was executed.
