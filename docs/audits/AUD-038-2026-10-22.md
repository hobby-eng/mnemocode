### Corrections

#### AUD-037-FUN004 — Medium — Reordered marked colors prune the correct placement

The supported reader accepts colors in any order. With the first color unread and moved to the end, the readable tags can look ordered for a later offset. The former in-order heuristic selected that offset and discarded the original phrase, in both Colors and Color Unicode. The correction keeps every start permitted by the readable tags. The shared 2²⁴ sum-of-combinations limit, candidate deduplication and refusals remain in force. The shared pre-dedup estimate for the two regression placements is 247,808 combinations (43,008 plus 204,800), or 15,488 checksum-filtered candidates; these estimates are not a claim about the exact number of unique yielded candidates. The tests include the public original phrase, 700 nonzero cyclic rotations/mark positions across all five phrase lengths, legacy-offset cases, both placements' candidates and unique yielded candidates. Rotations are not all permutations. The tiny startup check uses a literal published direct-12 placement and performs no search or cryptography.

#### AUD-004-API001 — Low — Nullish wallet evidence lacks the stable refusal code

A JavaScript caller could pass null or undefined and receive an intrinsic property-access TypeError. A non-null-object guard now runs before `.kind`, returning the existing `core.wallet-evidence.unsupported-bitcoin-evidence-kind` refusal. Valid derivation and signatures are unchanged.

#### AUD-038-UI001 — Low — Repeated SSKR display loses the full backup and fingerprints

After a mismatched written quorum, Show the result again cleared the screen and redrew shares but omitted the export heading, optional complete backup and fingerprints. One callback now redraws every displayed part in the original order. Saves remain outside it and run once. The temporary EncodedBackup is disposed per display. A unit regression observes only output after the repeat choice; real-PTY checks cover the persistent direct case and a supplemental masked 80×24 paged case with distinct original/encoded fingerprints and secret-free main screen.

#### AUD-038-BLD001 — Low — Monitor stop can look like success

The new wrapper originally forwarded the child exit code from the retained monitor. A real child handling SIGTERM with exit 0 reproduced the false-success status after a timeout. The wrapper now fails on any stopReason, retaining the original child status, wrapper status and hashes of both scripts. The one-second regression failed before the correction and passed afterwards. Independent read-only follow-up accepted the exact three harness files. The historical AUD-026 monitor remains unchanged; actual release receipts require both exitCode zero and no stopReason. This affected audit support, not program execution.

#### AUD-038-BLD002 — Low — Cached advisory answers labeled as live

Final support review caught a rerun defect in the newly added advisory harness: ordinary mode could reuse retained responses but report a new live check. A network-edge regression reproduced that behavior before correction. Live mode now always gets a fresh UTC-named folder and refuses existing response files; only explicit --cached replay can read them. The live fetch, refusal and cached replay cases pass without making network requests. The original fresh 21-query result and its hashes remain valid.

#### AUD-038-DOC001 — Low — Fix reference points to release notes

The draft JSON used cecdd9c as both the program fix and verification commit. The actual code correction is 1137905; cecdd9c changes the matching release notes. All three program remediation rows now name the former as fixCommit and the latter as verificationCommit. The original draft and negative check are retained; validation checks the distinction. Neither program bytes nor executed results changed.
