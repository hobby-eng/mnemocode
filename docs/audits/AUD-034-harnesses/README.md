# AUD-034 harnesses

These audit-only tools check the existing standalone MnemoCode checkout at HEAD `261aaedaedeb17ac1e32cd31371c850f740d2ba5`, including its recorded uncommitted remediation. They do not change production source, tests, dependencies or generated SSKR files.

`node docs/audits/AUD-034-harnesses/capture.mjs` freezes the actual source and instruction/procedure hashes, all 32 canonical check assignments, all applicable rule IDs and every trackable file's planned review depth. It refuses a changed expected source or an existing baseline. Inventories and hashes are not semantic review.

`AUD026_RSS_MIB=1152 AUD026_HEAP_MIB=256 AUD026_TIMEOUT_SECONDS=600 node docs/audits/AUD-034-harnesses/run.mjs LABEL COMMAND [ARGUMENTS]` reuses the frozen AUD-026 guard with this audit's local evidence destination. Labels are immutable. It records exact commands, UTC times, exit codes, source-before/after and log hashes, sampled process-tree RSS and available host memory. The 3 GiB OS reserve and guard limits are unchanged; a resource stop or admission refusal is not a test failure or pass.

`node docs/audits/AUD-034-harnesses/inventory.mjs` inventories current exported declarations and records exact, qualified admission of older semantic/canonical evidence. It uses the already installed TypeScript 5.9 parser only for metadata, not as the pinned TypeScript 7 compiler or proof of body review.

`AUD026_RSS_MIB=1152 AUD026_HEAP_MIB=256 AUD026_TIMEOUT_SECONDS=600 node docs/audits/AUD-034-harnesses/suite.mjs` discovers the actual default Vitest file universe and runs each file in a fresh process, serially with one worker. It preserves every receipt and JSON result, refuses overwrite and stops on a resource/admission refusal without automatic retry. `node docs/audits/AUD-034-harnesses/summarize.mjs` subsequently requires complete, non-overlapping membership and unchanged inputs before counting assertions; an incomplete run cannot become green.

Run commands from the repository root with its already installed pinned tools. Rust uses the workspace's documented Cargo/Rustup homes and one worker. Public vectors and synthetic data only. No installation, worktree, repository copy, publication or remote workflow dispatch is performed. Evidence is local-only under `docs/audits/AUD-034-evidence/`; the canonical Markdown/JSON report identifies exactly which commands ran and which prior semantic results were admitted by identity.

`node docs/audits/AUD-034-harnesses/release.mjs` runs the remaining documented local checks serially after complete suite evidence: full self-test, native and independent SSKR, actual PTY, real card/QR output, current same-source Linux acceptance, npm advisories and package dry-run. Set the workspace's Cargo/Rustup homes, `CARGO_BUILD_JOBS=1`, and an on-disk workspace `TMPDIR` first; no dependency installation is performed.

`node docs/audits/AUD-034-harnesses/history.mjs` validates the actual 31 published historical pairs with the existing system Python `jsonschema` tool used by earlier audit validation. AUD-023 is explicitly abandoned without a report. The earlier incorrect count assumption stays in original local evidence.

`node docs/audits/AUD-034-harnesses/close-error-probe.mjs` exercises the actual bounded-file reader with a synthetic public file. Only the OS close result is faulted; its real descriptor is closed. An allocation observer preserves original behavior and measures the unreturned result. The observer retires its public test bytes and removes its unique fixture directory.

`node docs/audits/AUD-034-harnesses/report.mjs` requires the completed source/reviewer, suite and explicit adjudication records before generating the English canonical pair. `node docs/audits/AUD-034-harnesses/validate.mjs` checks the canonical JSON schema with duplicate-key rejection, exact source/procedure/receipt/artifact identities, 32 checks, 53 CORE/104 total rule IDs, complete file coverage, privacy and unstaged evidence. ## Addendum 2026-10-20: inputs a reader cannot obtain

This documentation-only addendum answers AUD-037-DOC002; the scripts are unchanged. The sections above do not name every input. Most scripts read files that are not published. These files exist only on the maintainer's machine, so a reader cannot rerun the scripts that need them:

- `capture.mjs` reads AUD-032's machine-local `docs/audits/AUD-032-evidence/coverage.json` and five machine-local AUD-033 files under `docs/audits/AUD-033-evidence/`: `remediation/REMEDIATION-2026-10-16.json`, `arc002-2026-10-18/ARC002-CLOSURE-2026-10-18.json`, `protocol-review.json`, `interface-review.json` and `core-rule-dispositions.json`. It also hashes the procedure files of the neighbouring `multi-chain-wallet-tools` checkout and the workspace's instruction files from the private workspace repository. It refuses any source other than the fingerprint `a1293d752f9c3f0d7de2db1616a83aeebb6e89053c6eff4f128fdc0dc9f20e39`.
- `inventory.mjs` loads the TypeScript parser named above: version 5.9.3, from the workspace's scratch folder `../tmp/cancel-check/node_modules/typescript` beside the repository. The workspace repository ignores that folder, and it was installed from the range `^5.9.3`. The script also reads AUD-033's machine-local `remediation/initial-snapshot.json`, every file in `remediation/` and `arc002-2026-10-18/ARC002-CLOSURE-2026-10-18.json`. The JSON report keeps that last path in `canonicalBuild.record`; it is machine-local too.
- `report.mjs` reads AUD-033's machine-local `core-rule-dispositions.json`.
- `inventory.mjs`, `summarize.mjs`, `release.mjs`, `report.mjs` and `validate.mjs` read this audit's own machine-local evidence in `docs/audits/AUD-034-evidence/`, starting with the `snapshot.json` that `capture.mjs` wrote.
- `history.mjs` and `validate.mjs` run Python code that imports `jsonschema`, and they read the schema from the neighbouring checkout. No requirements file sits beside them, so they do not meet TOOL-03, and the version this audit used was not recorded. They read only published files: `run.mjs`, the command recorder; `suite.mjs`, after creating the ignored `docs/audits/AUD-034-evidence/` folder; `close-error-probe.mjs` with an unused result path; and the date-recovery `vitest` command above.
