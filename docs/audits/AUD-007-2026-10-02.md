### Findings

### AUD-007-ARC001 — Low — Material-sample comments promise stability across different collections

- **Category/status:** ARC / verified.
- **Release blocking:** no.
- **Affected files:** `src/export/material-artwork.ts:527–531`, `test/material-cards.test.ts:111–120`.
- **Reproduction:** After pnpm build, run node docs/audits/AUD-007-harnesses/local-invariants.mjs. Compare chooseMaterialSamples("vehicle", ["#000000"]) with the same reference in the five-color list.
- **Expected:** Comments describe deterministic assignment for a given collection and explain that adding other references can change its decorative sample.
- **Observed:** Source says "The same reference always gets the same sample"; test says "whatever comes with it". Greedy one-to-one assignment depends on the full collection. The test checks reversal/case and duplicates, not changed neighboring references.
- **Impact:** Misleading maintenance/test contract only. Exact printed hex references and QR payloads are unaffected, and the renderer supplies the whole collection when rendering a fragment. No recovery or confidentiality failure demonstrated.
- **Evidence:** local-invariants-host.log (local): #000000 alone -> Satin black; in [#000000,#000001,#000002,#FFFFFF,#FFFFFE] -> Matte racing green.
- **Recommended fix:** Qualify both comments with the collection context; if cross-collection stability is intended, design that separately rather than changing the recovery representation.
- **Required verification:** Keep the counterexample and confirm full-sheet versus individual-fragment consistency for the same collection and exact payload preservation.

### Informational observations and recommendations

- The SSKR relocation has no confirmed functional or security defect. The Rust bridge is byte-unchanged by the relocation; its current toolchain/dependencies and generated WASM were independently rebuilt.
- Dockerfile.sskr downloads x86-64 Node and rustup, but the production wrapper does not pass --platform linux/amd64. This audit used an explicit platform. Native ARM-host builds were not attempted; pin the canonical platform or document the x86-64 requirement before promising portable source builds.
- The new build wrapper has useful marker/loader guards but no dedicated tests for missing markers, Docker failure, a one-byte rebuilt mismatch or preservation of tracked files in --check. Add audit-only/fake-Docker regression coverage if extending this script; the current real compare passed.
- The existing AUD-005-BLD007 timing concern recurred on two card tests (one has its own 30 s timeout). Prefer bounded test concurrency over weakening assertions; current sequential rerun passed without raising limits.
- ci.yml lacks its own concurrency group; executable.yml cancels in-progress runs including tag runs. Consider matching the workspace policy to cancel superseded verification while excluding publication from cancellation. No interrupted release was reproduced.
- Removal of the network loader and hashes are integrity consistency checks, not signatures or protection against a host that can replace the application and manifest together.
