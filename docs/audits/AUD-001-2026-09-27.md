### Test and vector sufficiency

Good core arithmetic and SSKR negative coverage, insufficient for unconditional release acceptance. The number of vectors alone is not the criterion. Separate independent expected values, same-implementation regression fixtures and same-implementation round trips.

- **Strong existing coverage:** both BIP39 word-list hashes; 744 exhaustive entropy-tail/oracle cases across five entropy lengths and three date schedules; leap-year/century/invalid structured dates; legacy last-word recovery; representation/container negatives; SSKR malformed metadata with recomputed CRC, duplicate/mixed/insufficient shares and native secret-digest corruption.
- **Fixed MnemoCode vectors:** seven total: direct-12, checksum-valid Seedshift at 12/15/18/21/24 words, legacy-12. Only direct-12 currently has both fingerprint fields. These are useful regression anchors; they are not an independent proof for every public API.
- **SSKR vectors:** one official grouped set (eight shares, all 30 minimal quorums), five deterministic fixtures for 128–256-bit entropy, exact UR/RGB bytes and 16-of-16 boundary. The five generated fixtures intentionally use the same pinned bridge and do not constitute a second implementation.
- **Built-in versus development tests:** normal CLI startup checks fixed core values before processing; SSKR operations additionally perform the SSKR self-check. `self-test` adds the vector file, 75 round trips, QR adapter and representative assets. The complete Vitest suite is not run at every ordinary invocation, which is appropriate. FUN002 concerns missing catalogue coverage, not absence of the fixed startup guard.
- **Authorized additions:** 120 production threshold policies, safe file replacement and failure cleanup, error redaction, QR drawing-call raster decoding, startup failure on a damaged pinned digest, and six explicit expected-failure contracts for open audit findings. The test patch does not enlarge the runtime package or add dependencies.

**Remaining priorities:**

- Fix open functional/file-protection findings and turn six expected-failure tests into ordinary passing regressions.
- Validate required public catalogue coverage and pin its upstream provenance; add independent known answers beyond a single direct/legacy 12-word fixture. Current checksum-valid Seedshift has one fixed vector at each of five lengths; only direct-12 includes both fingerprints.
- Add local Bitcoin evidence coverage across native SegWit/Taproot/legacy/nested profiles, mainnet/testnet and path/passphrase boundaries, including case and malformed-address rules.
- Failure injection for RNG unavailable, partially completed image exports, renderer timeout, full disk and interrupted input; bounded malformed/large image/text tests.
- QR payload isolation for every SSKR layout and grouped-member length, long personal fields/glyph failures, colors at extremes, and exact partial last groups across all image/PDF forms.
- Canonical WASM rebuild, independent cross-implementation SSKR check, fresh pinned package-manager install and supported Node/platform runs.

### Code quality and human readability

The modular boundaries are real: a small public core facade delegates to seven transformation modules, while CLI orchestration, SSKR transport/runtime and visual rendering have separate owners. Comments explain the entropy-tail modulus, decimal color wire packing, top-origin PDF units, private replacement and export-local caches. These are useful explanations of constraints, rather than line-by-line narration.

The baseline owned code passes Prettier. Formatting alone does not eliminate nested layout decisions or long orchestration. The measured hotspots and limits are in AUD-001-ARC001 and `static-review.json`; counts are not defects by themselves. The largest help-text function should stay readable as text rather than being fragmented to improve a metric. The new tests also follow the formatter. #### AUD-001-SEC001 — Medium — Pinned development dependencies trigger two upstream security advisories

- **Category / status:** SEC / open.
- **Release blocking:** true.
- **Affected files:** `package.json:57`, `pnpm-lock.yaml`, `.github/workflows/ci.yml`.
- **Reproduction:** Run pnpm audit --audit-level high --json and pnpm audit --json against the reviewed lockfile. No exploit server was started.
- **Expected:** The configured high-severity dependency gate should pass, or an explicit reviewed exception should identify the exact unreachable configuration.
- **Observed:** npm reports GHSA-5xrq-8626-4rwp (critical) for vitest 3.2.4 and GHSA-82fw-gwwq-j7x9 (moderate) for both vitest and @vitest/mocker. These are two advisory root causes, not three independent vulnerabilities. Both audit commands exit 1.
- **Impact:** The affected packages are development dependencies. Reviewed scripts use vitest run; no first-party UI/API server or public mocker plugin configuration was found. This is a dependency/release-gate defect, not a demonstrated remote compromise of the offline CLI. Project severity is medium; upstream critical severity is retained separately. The second advisory requires a reachable development-server integration. No runtime production dependency advisory was reported by this registry snapshot.
- **Recommended fix:** Upgrade and pin a supported patched Vitest/mocker pair, regenerate the lockfile with the pinned package manager, then review compatibility and rerun tests and both audits. The registry lists >=4.1.11 for the mocker issue. For the first advisory, the registry says >=3.2.6 while the upstream advisory page says 3.2.5; retain this discrepancy and verify the chosen version against fresh authoritative records. Do not blanket-ignore the advisory or expose the test API.
- **Required verification:** A fresh registry audit clears both advisory IDs; the updated locked install, tests and CI pass. Confirm no test UI/API endpoint is introduced.
- **Evidence:** [dependency-audit.command.json](AUD-001-evidence/dependency-audit.command.json), [dependency-audit.log](AUD-001-evidence/dependency-audit.log), [dependency-audit-all.command.json](AUD-001-evidence/dependency-audit-all.command.json), [dependency-audit-all.log](AUD-001-evidence/dependency-audit-all.log), [static-review.json](AUD-001-evidence/static-review.json).

#### AUD-001-SEC002 — Medium — Input overwrite protection misses aliases of parent directories

- **Category / status:** SEC / open.
- **Release blocking:** true.
- **Affected files:** `src/cli/output-paths.ts:6`, `src/cli/output-paths.ts:24`, `src/export/private-file.ts:10`.
- **Reproduction:** Create real/input.txt containing the public zero-entropy mnemonic and a directory symlink alias -> real. Run encode --mode seedshift --mnemonic-file real/input.txt --dates 23-09-2026 --output alias/input.txt. The retained harness performs this only below a temporary audit directory.
- **Expected:** Reject output that resolves to the input before processing or publishing it; the input file must retain its bytes.
- **Observed:** Exit 0. real/input.txt is replaced by MNC1:seedshift:english:wool abuse actual ... congress. The overlap check compares path strings after resolve(), which does not resolve directory symlinks.
- **Impact:** A user can accidentally overwrite the only original input with a transformed record whose separate dates are required for recovery. Alias collisions can also bypass output/output separation. The ordinary writer safely replaces a final-component symlink; that distinct case passes and does not protect aliased parent directories. No attacker-controlled race or host privilege escalation was demonstrated.
- **Recommended fix:** Canonicalize existing parents and compare effective destination identities against all input and output paths. Preserve final-symlink replacement semantics, check at the publication boundary, and document the residual concurrent filesystem-race threat. Reject overlap rather than relying only on lexical preflight.
- **Required verification:** The retained source-alias CLI reproduction must fail without changing input bytes; cover output aliases, nested paths and non-existing children, while retaining the passing final-symlink and private-permission tests. Remove the expected-failure marker only after fixing production.
- **Evidence:** [output-alias.json](AUD-001-evidence/output-alias.json), [output-alias.log](AUD-001-evidence/output-alias.log), [test-remediation.patch](AUD-001-evidence/test-remediation.patch).

#### AUD-001-FUN001 — Medium — Valid uppercase Bech32 evidence rejects the correct recovered mnemonic

- **Category / status:** FUN / open.
- **Release blocking:** true.
- **Affected files:** `src/bitcoin-evidence.ts:248`, `src/bitcoin-evidence.ts:253`.
- **Reproduction:** Use the public abandon ... about mnemonic, native-segwit, mainnet, account/branch/index 0, and BC1QCR8TE4KR609GCAWUTMRZA0J4XV80JY8Z306FYU as address evidence.
- **Expected:** A valid uppercase Bech32 spelling and its lowercase equivalent identify the same witness program and match the same recovered mnemonic. Mixed-case encodings remain invalid; Base58 must not be lowercased.
- **Observed:** The installed address decoder accepts both spellings and returns identical witness hashes. matchBitcoinEvidence reports true for lowercase and false for uppercase because it compares strings directly.
- **Impact:** Date-recovery filtering can discard the correct candidate when a valid uppercase receiving address is supplied. No private-key corruption is involved. The failure is reproduced for BIP84; a BIP86 case is recommended, not claimed reproduced.
- **Recommended fix:** Parse and validate address evidence for its network, compare normalized semantic addresses/scripts, and apply case rules specific to Bech32/Bech32m. Keep Base58 case-sensitive.
- **Required verification:** Lowercase and uppercase BIP84/BIP86 addresses match; mixed case, wrong checksum, wrong network and different scripts fail clearly. Exercise recover-date through the CLI, not only the matcher.
- **Evidence:** [extra-probes.json](AUD-001-evidence/extra-probes.json), [extra-probes-retry.log](AUD-001-evidence/extra-probes-retry.log), [test-remediation.patch](AUD-001-evidence/test-remediation.patch).

### Informational observations and recommendations

#### AUD-001-ARC001 — Formatting is consistent; remaining complexity is concentrated in orchestration and rendering

All 76 baseline owned TS/test/JS-script files match the checked-in Prettier configuration. Maintained source has 63 TS files; the resolved static runtime import graph has no cycles. Metrics found 134 non-null assertions, 30 nested ternaries and 13 functions of at least 70 lines. The 316-line usage function is mostly help text and must not be treated as equivalent to a 117-line renderer. Five Markdown files fail formatting checks, without broken source-checkout links.

The code is modular and substantially easier to inspect than a single monolith. Formatting does not prove understandable contracts: main dispatch, preview/save orchestration and glass/material layout still require careful tracing. Raw counts are review prompts, not defects or a readability score.

**Recommendation:** Next readability pass: named renderer/input types, explicit branches for nested layout decisions, small named validation/publishing stages where they have distinct responsibilities, and comments explaining units, entropy-tail modulus, color wire order and ownership. Keep adjacent simple code together; do not split by line count alone. Pin a development formatter command rather than relying on an external cached CLI. Format Markdown in a separate documentation-only change.

**Verification:** Formatting and type checks plus existing visual fixtures remain unchanged after pure refactoring; reviewers can trace secret input to transform to export without following visual-layout internals.

#### AUD-001-SEC003 — Resource limits and exceptional cleanup need broader adversarial verification

SSKR records/counts and QR minimum module size have explicit limits. PNG input is read and synchronously decompressed without an application file-size/pixel budget; text input is also read in full. Reviewed code wipes selected owned entropy/random buffers and private derivation nodes in finally blocks. JavaScript strings and all WASM/transitive-library copies cannot be shown erased by these checks.

Large untrusted local inputs may exhaust memory or block the process. No host-exhaustion probe or exploit was attempted. Failure injection after every allocation, RNG failure and WASM panic-memory inspection remain unexecuted; normal negative tests do not establish those properties.

**Recommendation:** Set documented input byte/pixel/count budgets before allocation and isolate expensive parsing where appropriate. Add bounded failure injection for RNG, interrupted writes, renderer timeout and cleanup. State practical cleanup limits instead of promising perfect zeroization.

**Verification:** Bounded over-limit files fail before large allocation; failures leave no published partial output or secret-bearing logs. Inspect owned-buffer cleanup and native failure paths separately.

#### AUD-001-BLD002 — Pinned WASM hashes were verified; canonical rebuild and platform coverage remain incomplete

All seven pinned bridge/source/lock/declaration/generated-file hashes match. A fresh TypeScript build reproduces all 126 existing dist file hashes. Rust/cargo/rustfmt/wasm-bindgen are unavailable here; no canonical WASM rebuild was executed. Node 24.19.0/Linux was tested; the declared Node >=20 range and Windows/macOS were not. Available pnpm was 11.19.0, while package/CI pin 10.19.0; no fresh frozen install was performed.

Integrity checks establish consistency with local pinned bytes, not independent cryptographic review, provenance of every upstream crate, or reproducibility across machines. A clean Node build does not close native supply-chain evidence gaps.

**Recommendation:** Document and execute the canonical pinned native build in a controlled toolchain; compare bytes and licensing/provenance against full upstream revisions. Re-run frozen installation and acceptance on supported Node/platform versions before release.

**Verification:** Retain exact toolchain/container inputs, full revisions, commands and output hashes; qualify any unavoidable nondeterminism.

### Assessment and limitations

Release acceptance is **not granted**. Existing arithmetic and share-transport tests are substantial, but the open source-file protection and recovery defects, dependency gate and incomplete native/platform evidence prevent a clean release recommendation. No real wallet compromise, loss of cryptographic entropy or active network exfiltration by the ordinary CLI was demonstrated. That statement is bounded by the reviewed paths and executed checks, not a security guarantee.

- Full-scope audit with incomplete execution, not a fully executed end-to-end certification. All 32 procedure areas have an explicit outcome.
- Only public/synthetic secrets were used. No active wallet material, broadcast, publication, push, release or external message was used.
- No full Rust/WASM cryptographic review or canonical native rebuild; pinned hashes are integrity evidence only.
- No fresh frozen dependency install; pnpm available 11.19.0 differs from pinned 10.19.0. Linux/Node 24 only; other supported versions/platforms unexecuted.
- Dependency registry access was initially denied automatically, then explicitly authorized by the user and completed. No dependency update was performed. Security advisory reachability was source-assessed; no vulnerable server was exposed or exploited.
- No physical print/phone-scanner validation, exhaustive visual page inspection, resource-exhaustion testing, or exhaustive fault injection.
- The initial sandbox suite had 22 failures, many due to subprocess EPERM/empty output. The unchanged host rerun is the authoritative baseline: 3 failures. Both logs are retained.
- Initial full render matrix hit the 300-second harness limit with no completed aggregate evidence. The checkpointed retry completed all 128 cases. This was an audit harness timeout, not a reproduced application crash.
- The six original expected-failure contracts are historical snapshot evidence. Their assertions now run as ordinary passing regressions; see the dated remediation record.
- The existing tree was dirty and had no Git remote. HEAD alone does not describe the audited source; use the scoped manifest/source archive. Production was unchanged during authorized test remediation.
- Temporary harnesses and screenshot artifacts are evidence, not production inputs. Initial cache/output inventory was narrowed before publication; ignored user output contents are excluded.
