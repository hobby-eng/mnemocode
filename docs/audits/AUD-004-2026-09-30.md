### Findings

#### AUD-004-SEC001 — Low — File-size guards do not bound the actual read

- **Category:** SEC
- **Severity:** low
- **Status:** verified
- **Affected files and builds:** src/cli/input.ts:30-34; src/cli/qr-input.ts:41-44; README.md:126
- **Reproduction:** Run the public-data probe-input.py harness. It sends 2,097,245 bytes containing a valid public mnemonic followed by spaces through a finite FIFO, and compares a regular file with identical bytes.
- **Expected behavior:** The documented 1 MiB text-input limit must apply to bytes actually consumed, including non-regular files and changing files.
- **Observed behavior:** The regular file exits 1 with the size-limit error; the FIFO has stat.size=0 and exits 0 with a successfully encoded mnemonic. Both text and PNG readers use stat followed by an unbounded whole-file read; only the text case was exercised.
- **Impact:** A user-selected FIFO/device or growing file can consume memory beyond the advertised bound or wait indefinitely. No remote input service, theft, or wrong recovery was demonstrated; the probe used only 2 MiB.
- **Evidence:** Local: AUD-004-evidence/file-input-probe.log; AUD-004-harnesses/probe-input.py
- **Recommended fix:** Open once and read at most limit+1 bytes, rejecting overflow; either reject unsupported non-regular inputs or enforce the same bounded reader on them. Apply the same approach to QR file bytes before decoding.
- **Required verification:** Test exactly limit, limit+1, a finite FIFO, file growth and PNG byte limits without intentionally exhausting memory.
- **Release blocking:** false; Limited to the stated boundary or documentation; no demonstrated failure of valid mnemonic or SSKR recovery.

#### AUD-004-API001 — Medium — Unknown Bitcoin evidence kinds silently become a recovery non-match

- **Category:** API
- **Severity:** medium
- **Status:** verified
- **Affected files and builds:** src/bitcoin-evidence.ts:329-348; src/bitcoin-evidence.ts:254-282
- **Reproduction:** Call matchBitcoinEvidence with the public abandon/about mnemonic, kind="address-typo", profiles=["native-segwit"], value="irrelevant", and mainnet account/branch/index all zero. The exact executable command is in the Checks table and JSON command evidence.
- **Expected behavior:** An unsupported runtime discriminator should be rejected before derivation, rather than reported as a valid comparison that did not match.
- **Observed behavior:** The public JavaScript API returns {"matched":false,"kind":"address-typo"}. matchDerivedNode falls through and the outer function emits an ordinary negative result.
- **Impact:** An untyped integration or deserialized configuration can mistake a programming error for evidence against the correct wallet. The CLI constructs supported kinds and was not shown vulnerable; valid supported comparisons pass existing tests.
- **Evidence:** Local: AUD-004-evidence/public-api-probe.log
- **Recommended fix:** Validate the evidence kind against the supported set at entry, before reading variant-specific fields; make an unsupported switch branch fail explicitly.
- **Required verification:** Unknown/missing discriminators fail with stable non-secret-bearing errors. Retain positive and negative address, key, WIF, xpub and fingerprint cases.
- **Release blocking:** false; Limited to the stated boundary or documentation; no demonstrated failure of valid mnemonic or SSKR recovery.

#### AUD-004-DOC001 — Low — The unconditional atomic-publication promise excludes SSKR file writers

- **Category:** DOC
- **Severity:** low
- **Status:** verified
- **Affected files and builds:** SECURITY.md:39; src/export/sskr-cards.ts:175-180; src/cli/sskr-command.ts:155-159
- **Reproduction:** Run write-failure.mjs. The audit-only adapter simulates ENOSPC after writing 16 bytes at the final SSKR PDF path; it restores the filesystem adapter and removes its public-data output afterwards.
- **Expected behavior:** SECURITY.md promises that a file appears under its final name only after it is complete.
- **Observed behavior:** The export rejects the simulated write error, but a 16-byte partial PDF remains at the final path with mode 0600. SSKR PDF and record outputs write directly with wx; ordinary record/PDF exports use private staging.
- **Impact:** A failed export can leave an incomplete backup at the requested path, contrary to the blanket documentation promise. The command does report failure and permissions remain private; no successful corrupt backup or unauthorized disclosure is claimed.
- **Evidence:** Local: AUD-004-evidence/partial-write-probe.log; AUD-004-harnesses/write-failure.mjs
- **Recommended fix:** Either implement complete-file publication for SSKR outputs while preserving exclusive no-overwrite behavior, or narrow the promise and document cleanup/retry behavior on partial writes.
- **Required verification:** Inject partial writes and cancellation; verify no final partial file under an atomic contract, preserve pre-existing destinations, and keep private permissions.
- **Release blocking:** false; Limited to the stated boundary or documentation; no demonstrated failure of valid mnemonic or SSKR recovery.

#### AUD-004-DOC002 — Low — The documented default size of six- and eight-reference cards is stale

- **Category:** DOC
- **Severity:** low
- **Status:** verified
- **Affected files and builds:** README.md:339; src/export/glass-cards.ts:280-284
- **Reproduction:** Render individual cards using business-glass-6in1 and business-glass-8in1 with pageSize omitted; render-check.mjs measures the PDF media box.

- **Evidence:** Local: AUD-004-evidence/rendered-qr-corrected.log; AUD-004-harnesses/render-check.mjs
- **Recommended fix:** Describe individual cards as 90 x 50 mm; distinguish the proportions of decorative sheet artwork from physical separate-card dimensions.
- **Required verification:** Keep PDF media-box assertions for all three glass capacities with omitted and explicit page sizes.
- **Release blocking:** false; Limited to the stated boundary or documentation; no demonstrated failure of valid mnemonic or SSKR recovery.

#### AUD-004-DOC003 — Low — The SSKR fixture description overstates the Bytewords vector count

- **Category:** DOC
- **Severity:** low
- **Status:** verified
- **Affected files and builds:** docs/SSKR.md:106; vectors/sskr-v1.json:20-35

### Informational observations and recommendations

#### AUD-004-API002 — Numeric CLI format renumbering is an explicit compatibility change

All five named formats still work; format 3 remains unicode. MNC1 records store format names, so the numeric renumbering does not alter their interpretation. Old scripts using --format 4 change output and --format 6 fail. This is not purely visual. The audit does not infer an accidental defect from an intentional pending change.

**Recommendation:** Before adopting the new numbering, confirm that saved commands are migrated; prefer stable named formats in automation. Keep the changelog notice.

**Verification:** Current CLI format matrix passes; if old numeric commands must remain compatible, define and test an explicit migration policy.

#### AUD-004-BLD002 — Extend automated presentation and platform coverage

CI runs Linux types/build/tests/dependency audit, but not format:check or the independent actual-PDF audit matrix. This audit executed Linux only. Formatting, real rasterization and non-Linux regressions can escape the current gates; no additional platform failure was reproduced.

**Recommendation:** Add format checking, a small real PDF/QR smoke check, and a supported second-OS test job. Keep resource-intensive matrices separate.

**Verification:** Observe the added gates on the intended platforms; do not count this Linux audit as Windows/macOS validation.
