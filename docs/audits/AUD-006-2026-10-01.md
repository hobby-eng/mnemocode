### Finding

### AUD-006-DOC001 — Low — README implies SSKR `--output` files have an MNC1 record header

- **Category:** DOC.
- **Severity:** low.
- **Status:** verified on 2026-10-02 (open at the reviewed snapshot). See the remediation section.
- **Release blocking:** false; recovery is not broken because the dedicated SSKR instructions explain the share format, but the general record paragraph is overbroad.
- **Affected files:** `README.md`; `src/cli/encode-export.ts`; `src/cli/sskr-command.ts`; `docs/SSKR.md`.
- **Reproduction:** Read the README’s `--output PATH` paragraph and invoke `node dist/mnemocode.js encode --sskr --mnemonic <public abandon/about vector> --threshold 2 --shares 3 --output <new file>`.
- **Expected behavior:** The general versioned-record statement should be scoped to ordinary mnemonic `encode` output, or explicitly state that SSKR output is a different format.
- **Observed behavior:** README says “A file written with `--output PATH` starts with a header: `MNC1:...`.” The production ordinary path calls `serializeRecord(...)`, but the integrated SSKR path writes `shares.join("\n") + "\n"` directly. The generated file contains three `ur:sskr/...` lines and no MNC1 header. `docs/SSKR.md` correctly says it contains one share per line, so the instructions contradict each other.
- **Impact:** A reader can expect SSKR output to be an MNC1 record and misinterpret or mishandle their backup file. No secret was used; the reproduction used the published public BIP39 test phrase.
- **Evidence:** Local `sskr-output-format.log` and `sskr-output-shape.log`; source comparison of the two production output paths; README line 371 and SSKR guide line 20.
- **Recommended fix:** Change the README paragraph to say ordinary non-SSKR `encode --output` writes MNC1, and link to the SSKR guide for `--sskr` output.
- **Required verification:** Run a text-only public-vector check for ordinary MNC1 and SSKR UR output; confirm each documented format matches its production entry point.
