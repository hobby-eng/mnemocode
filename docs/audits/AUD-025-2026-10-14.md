### Findings

#### AUD-025-API001 — Medium — A final host cancellation hands out an assessment plan or throws the cancellation value

- **Category:** API.
- **Severity:** medium.
- **Status:** fixed.
- **Release blocking:** false for the corrected finding; no release acceptance is implied.
- **Affected files and builds:** `src/sskr/share-restore.ts`, `src/cli/share-repair.ts`, `test/sskr-share-modules.test.ts`.
- **Reproduction:** Abort the host signal after the assessment step has returned, before the watch callback gives its result to ShareRestore.read. The retained late-assessment-red command records the failing cancelled case; the live callback control passes.
- **Expected behavior:** Return kind=stopped, publish no live plan or timing callback, and wipe the unpublished plan. User cancellation is an outcome (CORE-22).
- **Observed behavior:** Before remediation the final abort was missed at the library handoff, and the CLI post-await throwIfAborted path threw CANCELLED.
- **Impact:** Supported library/CLI cancellation can continue into assessment output or become an error. No incorrect restored entropy or unauthorized spending was demonstrated.
- **Evidence:** source SHA-256 locations in the paired record; relevant command identities above and in its complete local-evidence ledger.
- **Recommended fix:** Capture the assessment signal at the shared library boundary, check it before report/handoff, and use the existing finally cleanup. Remove the CLI throwIfAborted duplication.
- **Required verification:** Cancelled and live final callback controls; existing share/terminal cancellation tests; Linux PTY. Current focused checks pass, but fix and verification commits are not yet recorded.

#### AUD-025-SEC001 — Medium — Rejected selectors can repeat a seed phrase supplied in the wrong field

- **Category:** SEC.
- **Severity:** medium.
- **Status:** fixed.
- **Release blocking:** false for the corrected finding; no release acceptance is implied.
- **Affected files and builds:** `src/record.ts`, `src/core/dates.ts`, `src/cli/command-line.ts`, `src/cli/option-copy.ts`, `test/error-privacy.test.ts`.
- **Reproduction:** Supply the public BIP39 zero-entropy phrase as an unsupported record mode/format, month, command/help topic or option name. Initial compiled record probes observed echoes; the original branches and migration inventory retain the interpolated messages. No separately timestamped pre-fix privacy command log was retained.
- **Expected behavior:** A refusal never repeats untrusted selector text, which may contain private material (CORE-24). Known program-owned option labels remain useful.
- **Observed behavior:** Original record/calendar/command refusals interpolated supplied selector text; the unknown-option label fallback returned the supplied name.
- **Impact:** An accidental paste or an untyped host routing private text into metadata can copy that text to displayed or retained errors. Local disclosure only was demonstrated with public data; host compromise, shell argument history and intentional exports are outside this fix.
- **Evidence:** source SHA-256 locations in the paired record; relevant command identities above and in its complete local-evidence ledger.
- **Recommended fix:** Use generic unknown-selector messages and avoid coercing rejected objects. Derive known card-option labels from one owned metadata source.
- **Required verification:** Seven current privacy regression cases and the compiled contract harness pass. Wider arbitrary text/host-error confidentiality and browser UI behavior are not established.
