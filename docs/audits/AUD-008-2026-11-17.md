# AUD-008 — MnemoCode 0.2.0 pre-release audit

**Release decision: hold.** The reviewed source has 34 new findings (12 medium, 22 low); 14 block release. No critical/high issue was confirmed in this review. This is not a statement that no such issue exists.

The main risks concern private terminal output, diagnostic disclosure, recovery edge cases and incomplete release gates. Basic encoding works: the bounded public-input probe passed 65 encode/read/decode combinations. Nine regression assertions fail: eight support current findings, while the prefix-helper assertion was withdrawn after an independent contract review and a passing documented CLI control. Documentation and built-in help were reviewed separately from implementation; twelve current documentation defects and a residual earlier Windows-documentation defect remain.

### Findings

#### AUD-008-SEC001 — Medium — Legacy recovery word reaches terminal scrollback outside the private screen

- **Category / status:** SEC / open.
- **Release blocking:** Yes; this affects a required recovery, security, integration or enforced release gate.
- **Evidence:** `crates/mnemocode-cli/src/commands/encode.rs:260`; `crates/mnemocode-cli/src/terminal.rs:224`; Local evidence: legacy-terminal-route.log (executed, exit 0); CLI SHA-256 c42e109da8fbccbb60a4646834fd5ced417e946e729359c6e38331c2941cab3a.
- **Reproduction:** Run encode with the public BIP39 zero-entropy phrase, date 23-09-2026, seedshift-legacy and indexes. Redirect stdin from /dev/null and stdout to a file, leaving stderr attached to a non-dumb PTY.
- **Expected:** Sensitive result lines use secret_channel and are never printed on an unprotected terminal.
- **Observed:** The PTY received 'Word to remember: addict'. print_last_word selects Channel::Error based on redraw capability, not private-screen state.
- **Impact and limits:** The displaced masked word is recovery material. This is a confirmed partial-secret disclosure to scrollback, not disclosure of the entire seed or an assertion of remote compromise.
- **Recommended fix:** Route the complete legacy recovery-word section through the existing secret-output policy.
- **Required verification:** PTY tests with independently redirected stdin/stdout/stderr; assert no word appears outside the alternate screen, including error and cancellation paths.

#### AUD-008-SEC002 — Medium — Unescaped discovered filenames can issue terminal control sequences

- **Category / status:** SEC / open.
- **Release blocking:** Yes; this affects a required recovery, security, integration or enforced release gate.
- **Evidence:** `crates/mnemocode-embroidery/src/found.rs:438`; `crates/mnemocode-cli/src/card_files.rs:321`; `crates/mnemocode-cli/src/card_files.rs:353`; Local evidence: regression-harness-final.log; intended regression assertion failed while its public-fixture controls passed.
- **Reproduction:** Give a synthetic backup filename containing ESC[?1049l; collect it and present the resulting notice or choice in the terminal.
- **Expected:** File paths are displayed as inert text; private-screen state cannot be changed by file content or names.
- **Observed:** The executed collector assertion preserves the ESC byte. Static tracing finds no escaping before notice/choice rendering; ESC[?1049l is the terminal alternate-screen exit sequence. Private-screen bookkeeping is not updated by that sequence.
- **Impact and limits:** A specially named local or imported file can inject terminal control bytes into subsequent display. An actual emulator transition was not executed in this audit, nor was a remote delivery path or arbitrary code execution established.
- **Recommended fix:** Escape control characters in filesystem-derived display strings while keeping original paths for access.
- **Required verification:** Check single-result notices, multiple choices, nested folder names and control bytes; use a PTY to verify private-screen continuity.

#### AUD-008-SEC003 — Low — Public Debug implementations expose QR data and legacy recovery hints

- **Category / status:** SEC / open.
- **Release blocking:** No; track for correction without claiming a separate security blocker.
- **Evidence:** `crates/mnemocode/src/qr/admission.rs:180`; `crates/mnemocode/src/backup.rs:96`; `crates/mnemocode/src/recovery/shares/unmasking.rs:67`; Local evidence: regression-harness-final.log; intended regression assertion failed while its public-fixture controls passed.
- **Reproduction:** Create a QR PNG from a public fixture, admit it and format the result using Debug. Separately format Encoding and ShareUnmasking with known recovery words.
- **Expected:** Diagnostic formatting redacts secret-bearing data.
- **Observed:** Admitted derives Debug over its entire borrowed PNG. Encoding and ShareUnmasking also print the recovery-word index.
- **Impact and limits:** A caller's debug logging can preserve the full recoverable QR image. Automatic production logging was not established; the smaller hint exposure has the same redaction root cause.
- **Recommended fix:** Implement redacted Debug for secret-bearing public results and audit variants of the same pattern.
- **Required verification:** Normal and pretty Debug must omit bytes, reversible encodings and original_last_word/last_word values.

#### AUD-008-FUN001 — Medium — Legacy embroidery and share producers discard the exact-recovery word

- **Category / status:** FUN / open.
- **Release blocking:** Yes; this affects a required recovery, security, integration or enforced release gate.
- **Evidence:** `crates/mnemocode-embroidery/src/phrase.rs:169`; `crates/mnemocode/src/sskr/split.rs:205`; `crates/mnemocode-cli/src/commands/stitch.rs:268`; `crates/mnemocode-cli/src/commands/sskr_split.rs:264`
- **Reproduction:** Create Original Seedshift backup, embroidery and SSKR shares for the same public phrase/date. Compare the returned or displayed original_last_word and restore a fixture with multiple valid candidates.
- **Expected:** Every producer of checksum-corrected Original Seedshift retains and safely exposes the extra word needed to choose the original phrase.
- **Observed:** Plain Backup::encode retains the word; written_entropy keeps only entropy and split_backup keeps shares/held phrase. Their CLI/binding results do not expose the discarded word.
- **Impact and limits:** Correct dates can leave multiple possible seeds; the heirs sheet assumes a word was supplied. Other wallet evidence can still distinguish candidates, so irreversible loss is not asserted.
- **Recommended fix:** Carry the recovery hint through all native and browser producer results and display it through the private-screen policy.
- **Required verification:** Round trip plain, share and embroidery outputs on a multi-candidate public fixture; the saved hint must uniquely recover the original.

#### AUD-008-FUN002 — Medium — Folder collection drops different groups' same-numbered SSKR members

- **Category / status:** FUN / open.
- **Release blocking:** Yes; this affects a required recovery, security, integration or enforced release gate.
- **Evidence:** `crates/mnemocode-embroidery/src/found.rs:195`; `crates/mnemocode-embroidery/src/found.rs:375`; `crates/mnemocode/src/sskr/set.rs:132`; Local evidence: regression-harness-final.log; intended regression assertion failed while its public-fixture controls passed.
- **Reproduction:** Create two required groups, each 1-of-1, using deterministic public randomness. restore_complete accepts the two original shares. Add them through Collector and examine the result.
- **Expected:** Identity is (group_index, member_index), and eligibility uses the complete SSKR topology.
- **Observed:** Only member_index is used for deduplication; the last member_threshold determines apparent completeness. One of two required shares is dropped and the result can still appear complete.
- **Impact and limits:** An explicitly supported imported grouped set cannot be recovered through discovery despite a sufficient original quorum. Core restoration from the full explicit list remains available.
- **Recommended fix:** Use the core topology and identity rules; reject conflicting copies and inconsistent metadata explicitly.
- **Required verification:** Test multi-group thresholds, overlapping member numbers, identical duplicates, conflicting duplicates and permutations. Include browser collection.

#### AUD-008-FUN003 — Medium — An incomplete surplus card share makes a sufficient set unavailable

- **Category / status:** FUN / open.
- **Release blocking:** Yes; this affects a required recovery, security, integration or enforced release gate.
- **Evidence:** `crates/mnemocode-embroidery/src/found.rs:303`; `crates/mnemocode-embroidery/src/found.rs:377`; `crates/mnemocode-cli/src/card_files.rs:315`; Local evidence: regression-harness-final.log; intended regression assertion failed while its public-fixture controls passed.
- **Reproduction:** Collect complete card representations of two shares of a 2-of-3 set, plus an incomplete third share missing an internal card.
- **Expected:** Determine recoverability from usable shares while reporting damaged surplus inputs separately.
- **Observed:** The first card-part error is copied into set.trouble and excludes the entire set, regardless of the already available quorum.
- **Impact and limits:** Recovery is unnecessarily refused when all files are selected together. Selecting only the two complete shares is a workaround.
- **Recommended fix:** Separate per-share parse errors from set topology; do not discard integrity warnings or silently accept conflicting usable shares.
- **Required verification:** Two complete plus one incomplete must restore with a warning; an actually insufficient or inconsistent quorum must still refuse.

#### AUD-008-FUN004 — Medium — A card word-count choice leaks into later input retries

- **Category / status:** FUN / open.
- **Release blocking:** Yes; this affects a required recovery, security, integration or enforced release gate.
- **Evidence:** `crates/mnemocode-cli/src/card_files.rs:154`; `crates/mnemocode-cli/src/commands/given.rs:242`; `crates/mnemocode/src/recovery/reading.rs:184`
- **Reproduction:** Select 12 words for a card backup that fails validation, then use Read another file to supply a valid 24-word text backup without --words.
- **Expected:** Replacing the input clears metadata belonging only to the previous selection.
- **Observed:** The process-global CHOSEN_WORDS is reused for non-card input; the reader truncates the replacement to its leading codes.
- **Impact and limits:** Valid recovery input can fail or produce a misleading shorter candidate after a retry. The same input in a fresh process is unaffected.
- **Recommended fix:** Bind the count to the selected backup and clear it whenever that selection changes.
- **Required verification:** PTY regression for 12-to-24 and 24-to-12 replacements, text and QR inputs, including explicit --words.

#### AUD-008-FUN006 — Medium — A wrong hint for the first share candidate aborts the remaining search

#### AUD-008-FUN005 — Info — Withdrawn: legacy prefix helper was tested against a stronger contract than documented

- **Category / status:** FUN / withdrawn.
- **Release blocking:** No; informational or withdrawn, not counted among confirmed findings.
- **Evidence:** `crates/mnemocode/src/backup.rs:278`; `crates/mnemocode-cli/src/commands/decode.rs:181`; `crates/mnemocode-cli/src/commands/decode.rs:729`; `README.md:178`; Local evidence: regression-harness-final.log, legacy-prefix-cli-corrected.log and legacy-prefix-explicit-length.log.
- **Reproduction:** The audit test appended three decoys to a legacy backup and unwrapped shorter_phrases. A closing-CLI probe omitted --words; a control supplied --words 12.
- **Expected:** The published helper contract permits propagating refusals; documented recovery with extra codes specifies the original length.

- **Required verification:** A future interactive test must distinguish the primary invalid input from optional diagnostic failure and verify the documented explicit-length route.

#### AUD-008-SEC004 — Info — Kept's nested strings depend on the native-host allocator contract

- **Category / status:** SEC / accepted.
- **Release blocking:** No; informational or withdrawn, not counted among confirmed findings.
- **Evidence:** `crates/mnemocode-cards/src/printed.rs:26`; `docs/LIBRARY.md:84`
- **Reproduction:** Trace Kept and its nested String/Vec ownership and the documented ZeroingAllocator requirement.
- **Expected:** Assess the supported host contract rather than assume an allocator configuration the library explicitly delegates to its host.
- **Observed:** Kept redacts Debug but has no independent zeroizing Drop. The CLI and WASM register ZeroingAllocator; native-host general-allocation wiping is explicitly delegated to that allocator.
- **Impact and limits:** No separate secret-lifecycle violation was established within this reviewed contract. Directly protected nested buffers would reduce reliance on host setup.
- **Recommended fix:** Consider stronger local ownership as hardening; keep native-host obligations explicit.
- **Required verification:** If ownership changes, exercise nested allocation growth and drop under the supported host configuration.
