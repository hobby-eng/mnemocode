# AUD-007 · MnemoCode 0.2.0 pre-release audit

**Decision: hold release.** The public WASM card exporter can switch from a hidden QR to an ordinary readable backup QR after a setting is turned off. The maintainer signing step accepts an incomplete draft and does not bind build provenance to the intended release. Both require correction and independent verification before publishing.

## Findings

### AUD-007-BLD001 · The signing step can approve an incomplete draft or artifacts from a different build of this repository

**High · release blocker.** Someone following the documented signer can endorse an incomplete or unintended build. No draft was signed during this review.

Inspection: Trace check_draft and each gh attestation verify argument before gpg. A nonempty internally consistent list of version-prefixed files is accepted. Artifact checks constrain the repository only. CI also attests the manifest, but the signer does not verify its attestation.

Expected: Verify the exact five CLI filenames, their five notice files and the WASM archive. Bind each digest and the checksum manifest to the authorized release workflow, tag and source commit.

Correction / verification: Derive the release inventory from one explicit specification and verify provenance against the authorized workflow and immutable tag commit before invoking GPG. Offline fixtures for missing and extra assets and incorrect provenance, plus a complete matching fixture.

Evidence: `xtask/src/release.rs:443`, `xtask/src/release.rs:548`, `.github/workflows/release.yml:212`.

### AUD-007-API001 · Reusing a CardExport can put a readable backup QR on a card after hidden QR is disabled

**High · release blocker.** A consumer that reuses the public object may print the recoverable backup as an ordinary QR. The inspected consumer creates a fresh object; no field incident was observed.

Inspection: Create a card with ordinary QR disabled, enable hidden QR, disable it, then export on that same object. Compare with a fresh QR-disabled object. The generated WASM and its public reader completed this test on three public-fixture A6 cards. Enabling hidden QR overwrites card_qr. Disabling clears hidden_qr only. The sheet layout sees ordinary QR enabled and a backup payload. Public fixture returned: ordinary QR reader returned public backup, initial QR off: false after enabling and disabling hidden QR: true.

Expected: Disabling the hidden layer restores the original ordinary-QR preference.

Correction / verification: Keep the ordinary and hidden QR preferences independent and resolve the drawing policy when exporting. Check both starting settings, repetitions and both toggle orders through the public generated WASM binding and an ordinary scanner.

Evidence: `crates/mnemocode-wasm/src/cards.rs:139`, `crates/mnemocode-wasm/src/cards.rs:191`, `crates/mnemocode-wasm/src/cards.rs:215`, `crates/mnemocode-cards/src/sheet/frame.rs:488`, `AUD-007-evidence/browser-smoke.mjs (local)`, `AUD-007-evidence/browser-card-verified.log`.

### AUD-007-BLD002 · The parity-vector release gate can select the wrong Git repository

**Medium.** The release gate is red on this checkout even with valid recorder bytes.

Inspection: Run xtask code-rules with a sibling folder containing a .git directory without a usable HEAD beneath a parent Git checkout. Git resolved the parent repository. The gate failed with “not a tree object”. All seven pinned upstream recorder digests matched on an independent check.

Expected: Verify parity against the pinned TypeScript project or identify explicitly which prerequisite is missing.

Correction / verification: Check the canonical top level and repository identity and handle a missing checkout explicitly. Exercise a real sibling, an absent sibling, and an incomplete nested checkout.

Evidence: `xtask/src/code_rules/deps.rs:317`, `AUD-007-evidence/code-gate.log`, `AUD-007-evidence/pinned-recorders.log`.

### AUD-007-SEC001 · Public diagnostic formatting exposes backup material

**Medium.** A library consumer can persist recoverable material in diagnostic logs. No call doing so was identified in the shipping CLI.

Inspection: Inspect derived Debug for Record and WrittenBackup, including borrowed strings. Debug prints backup contents and, for WrittenBackup, also the supplied dates.

Expected: Formatting a public secret-bearing type redacts its contents.

Correction / verification: Remove or redact Debug on both types. Use a public fixture and check all Debug representations for the fixture values.

Evidence: `crates/mnemocode/src/backup/record.rs:54`, `crates/mnemocode/src/recovery/backup_check.rs:193`.

### AUD-007-SEC002 · Private-screen clearing does not cover a separate output terminal

**Medium.** A second output terminal can retain a displayed phrase after the prompt says to clear. Intentional plain file and pipe export is a separate contract.

Inspection: Trace alternate-screen entry, decode output and screen clearing when stdin/stderr and stdout refer to different terminals. The private screen is entered on stderr; decoded results can go to stdout. The TTY checks do not compare their device identities.

Expected: All screen-only sensitive output uses the terminal entered and cleared by the application.

Correction / verification: Route screen-only results to the private terminal or verify identical terminal devices before treating stdout as private. Test two disjoint PTYs with a public fixture. Retest intentional piping and the ordinary shared-terminal path.

Evidence: `crates/mnemocode-cli/src/terminal.rs:189`, `crates/mnemocode-cli/src/terminal/private.rs:300`, `crates/mnemocode-cli/src/terminal/result.rs:29`, `crates/mnemocode-cli/src/commands/decode.rs:281`.

### AUD-007-SEC003 · An unreadable zram backing-device attribute can suppress the swap warning

**Low.** The CLI can omit a useful warning on a restricted configuration.

Inspection: Trace the error branch for backing_dev with an unreadable sysfs attribute. Read failures take the same safe branch as a missing backing device.

Expected: Distinguish unavailable evidence from a known RAM-only device.

Correction / verification: Distinguish not-found, explicitly unbacked, and unreadable states. Check public synthetic sysfs trees for each case.

Evidence: `crates/mnemocode-cli/src/os/swap.rs:104`, `SECURITY.md`.

### AUD-007-SEC004 · Memory lock warnings can be lost on operation failure

**Low.** A user may miss the reduced protection on an unsuccessful operation.

Inspection: Read the ordering of command dispatch, error propagation and memory-lock reporting. Early return from the operation bypasses the post-command lock warning.

Expected: A failed lock is reported after handling secrets even when the operation later fails.

Correction / verification: Collect lock status on all return paths while preserving the original error. Exercise successful and failing public operations with a simulated lock failure.

Evidence: `crates/mnemocode-cli/src/gate.rs:119`.

### AUD-007-FUN001 · A paper transcription of all printed columns can select the wrong SeedStitch legend format

**Medium.** Manual recovery from an older-format printed sheet may fail. The canonical two-column input and embedded PDF recovery remain available.

Inspection: Compare a printed older-format legend with the parser chosen by the number of typed fields. Both formats print DMC; three typed fields select the ordered format even when the sheet was created using the older checksum domain.

Expected: A person copying the fields printed on the paper can select the intended checksum and ordering rules.

Correction / verification: Identify the format on paper, document the exact columns per mode and address ambiguous imports explicitly. Recover a public example of each paper format by typing what the sheet instructs, without the original PDF.

Evidence: `crates/mnemocode-embroidery/src/chart.rs:246`, `crates/mnemocode-embroidery/src/legend.rs:313`, `docs/MANUAL_RECOVERY.md:121`.

### AUD-007-FUN002 · The physical-size picker can show its lower bound above its upper bound

**Low.** A valid small drawing appears impossible to size.

Inspection: Inspect the inward rounding of a single stitch-width interval. A 40 by 40 picture on 14-count Aida permits 40 stitches. Independent rounding yields 7.3 cm as the lower bound and 7.2 cm as the upper bound. Public fixture returned: width interval 7.3 7.2 accepted stitches at lower endpoint 40.

Expected: Both displayed endpoints form a nonempty range with an accepted width.

Correction / verification: Construct the displayed interval from the actual typed-width acceptance condition. Test singleton intervals and both proposed bounds across fabric counts.

Evidence: `crates/mnemocode-embroidery/src/fabric.rs:285`, `AUD-007-evidence/browser-smoke.mjs (local)`.

### AUD-007-FUN003 · Embroidery sampling arithmetic can overflow on 32-bit WASM

**Medium.** An accepted aspect ratio can produce incorrect sampling or an operation failure in the browser.

Inspection: Inspect intermediate products in span and compare with the whole-image pixel limit and target pointer width. An intermediate index-times-pixels product uses usize. A pixel-count bound alone does not bound that product to 32 bits for very elongated inputs.

Expected: Accepted dimensions yield valid sampling coordinates on native and WASM targets.

Correction / verification: Use widened checked arithmetic or document and enforce dimension limits that cover the intermediate products. Use bounded arithmetic unit tests on extreme legal dimensions, including a wasm32 target.

Evidence: `crates/mnemocode-embroidery/src/picture.rs:259`.

### AUD-007-API002 · The browser embroidery PDF reader lacks the CLI whole-input bound

**Medium.** A consumer assuming the CLI limit also protects the browser can exhaust tab memory. No large PDF was created or read in this audit.

Inspection: Compare the browser binding, shared PDF piece scanner and CLI file-admission checks. The browser path scans the supplied document. The inner piece limit does not cap the whole PDF.

Expected: A whole-input limit applies before large data crosses the browser binding or is scanned.

Correction / verification: Expose a binding boundary that checks the length before copying and enforces the documented PDF limit and header policy. Boundary tests for both entry points using length-level fixtures and small representative documents.

Evidence: `crates/mnemocode-wasm/src/embroidery.rs:299`, `crates/mnemocode-cli/src/input.rs:145`, `crates/mnemocode-cards/src/pdf/piece.rs:42`.

### AUD-007-DOC001 · The manual overstates detection of DMC transcription changes

**Low.** A person may rely on a stronger transcription check than the paper format supplies.

Inspection: Compare the stated protection with the inputs to the ordered legend checksum. A different valid DMC value preserving relative order can leave the checksum input unchanged.

Expected: Specify exactly which DMC changes are detected.

Correction / verification: Describe rank protection and its limits, preserving compatibility. Add one rank-preserving and one rank-changing example to tests and docs.

Evidence: `docs/SEEDSTITCH.md:73`, `docs/SEEDSTITCH.md:144`, `crates/mnemocode-embroidery/src/legend.rs:695`.

### AUD-007-DOC002 · Release verification instructions do not bind success to the executable selected by the user

**Medium.** A reader can believe the intended executable has been verified when only another file was checked.

Inspection: Read the verification steps as separate shell commands and check which filenames --ignore-missing verifies. The commands may continue after failure. A match for a different present manifest entry does not authenticate the chosen filename.

Expected: Failure stops the procedure and the exact executable to be run has a signed matching digest.

Correction / verification: Provide fail-fast commands matching the exact platform filename, verify its digest and require the trusted signing fingerprint. Verify the documented instructions with the target missing, renamed, changed, and with a valid unrelated asset present.

Evidence: `docs/CLI.md:11`.

Expected: Release documentation identifies a complete measured result, exclusions and supported scope.

Correction / verification: Finish coverage on a suitable machine, publish the result with the exact scope and link it. Verify the post-fix test log and coverage inputs against the final release tree.

## Limitations

- Hundreds-of-templates suites explicitly excluded, including the 468-case QR layout matrix, ignored page_qr permutations and expensive large_exports. cargo xtask features would enable ignored suites. No mass PDF or page-image rendering was run.
- Fresh cross-platform native execution, full release CI, duplicate Docker image builds, signed tag verification and public release signing were not performed. No tag was created.
- Coverage at the inspected source snapshot has no complete record. Historical 64.21% line coverage is partial and cannot be reported as final release coverage.
- One public input corpus plus focused regressions cannot establish the absence of all secret copies or layout defects. Physical print/scan behavior, Windows live policy and the complete downstream browser UI were not exercised.
- Inventory coverage counts tracked files by digest. Static review and tests focus on the source paths recorded here. A file digest is not a line-by-line semantic review.
- Large or interrupted checks retain their true exit status. Results from tests run more than once must not be added.
