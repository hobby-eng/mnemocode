# MnemoCode in Rust: threat model

Scope: the `mnemocode` executable on Linux, macOS and Windows, and the `mnemocode.wasm` file each
wallet-tools page embeds. Measure ids are those of
`design/platform/protections.json` (32 required, 9 optional, 25 rejected); this file uses the
required ones and says where the design adds to them. "Refuse" means a secret command stops before
it asks for any secret; "report" means the startup checks, the Protection line and the self-test
name it (ADR 0008).

## Assets

| Id  | Asset                                                                                         | Secret    |
| --- | --------------------------------------------------------------------------------------------- | --------- |
| A1  | Seed phrase, entropy, seed, private keys (BIP32, WIF)                                         | yes       |
| A2  | Seedshift dates: with masked codes they give A1                                               | yes       |
| A3  | Codes and MNC1 records: in direct mode they are A1; masked, A1 with A2                        | yes       |
| A4  | Shares: a quorum gives A1 or a masked phrase                                                  | yes       |
| A5  | BIP39 passphrase, candidate-list passphrase, the Discovery Scanner's one-time X25519 identity | yes       |
| A6  | Candidate lists of a search                                                                   | yes       |
| A7  | Exports holding A3 or A4: cards, sheets, page images, QR images, share files, records         | yes       |
| A8  | Correct results: a backup that does not restore loses A1 as surely as a thief takes it        | integrity |

Fingerprints, xpub and address evidence and the Scanner's recipient key are not secret; they are
worded by DOC-05.

## Adversaries and entry points

| Id  | Adversary                                               | Reaches through                                                                |
| --- | ------------------------------------------------------- | ------------------------------------------------------------------------------ |
| D1  | Another process of the same user, without root          | ptrace, `/proc/PID/mem`, `process_vm_readv`, ReadProcessMemory                 |
| D2  | A crash handler, or whoever reads its store             | core files, apport, systemd-coredump, WER                                      |
| D3  | Whoever holds the disk later                            | swap, hibernation image, leftover or half-written files                        |
| D4  | Code inside the process: a faulty or hostile dependency | sockets, io_uring, file writes, started programs                               |
| D5  | Other users, sync clients, onlookers                    | readable files, synced folders, screen, scrollback, clipboard                  |
| D6  | Crafted input                                           | PNG and QR files, candidate files, records, share text, dates, oversized input |
| D7  | A DLL planted beside the executable                     | the Windows DLL search order                                                   |
| D8  | Page or dependency code in the browser, other origins   | network APIs, storage, linear memory                                           |
| D9  | The person's own slip                                   | a secret in argv, the environment or shell history; a phrase in a wrong field  |
| D10 | A changed build input                                   | crates, vendored engine, toolchain, assets, release files                      |

Entry points: argv and environment (E1), standard input (E2), the secret file options (E3), the
private-screen prompt (E4), QR image files (E5), candidate files and recipients (E6), output paths
(E7), system files read at start: `/proc`, `/sys`, the registry (E8), the WASM API (E9), build and
release inputs (E10).

## Out of scope

- An adversary with root, the kernel, a hypervisor or firmware; hardware attacks (cold boot, DMA,
  power or EM side channels).
- Same-user code that runs before the program or changes it: a modified executable, LD_PRELOAD,
  a debugger attached at launch on Windows (W-MEMORY-READERS is rejected: a process's owner can
  change its DACL, and PPL needs Microsoft signing),
  keyloggers and screen capture. The signed release protects the download, not the account.
- A hostile browser or extension; JavaScript strings a page holds, which cannot be wiped (DOC-07).
- Register and native stack temporaries of dependencies (the bip39 crate's PBKDF2 pads and HMAC
  states among them; bitcoin_hashes does not zeroize): native memory is out of D1's and D2's
  reach by T1 and T2. D3: such pages, and owners over the lock budget, may reach swap; only the
  swap warning (L-SWAP-CHECK) answers it, since L-MLOCKALL is rejected.
- Timing side channels beyond comparing secrets in full length; the curve and hash crates are
  constant-time where it matters.
- Printed cards and sheets once printed; the person's storage of shares.
- Network providers: MnemoCode has no network code; the Discovery Scanner's are wallet-tools'.
- Measures the platform report rejects, each with its reason in `protections.json` (guard pages,
  WIPEONFORK, mlockall, RLIMIT_AS, AppContainer, COOP/COEP and others).
