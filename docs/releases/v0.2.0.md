MnemoCode 0.2.0 is the first release written in Rust. It is one executable for Linux, macOS or Windows with nothing else to install; on Linux it needs glibc 2.35 or later, as in Ubuntu 22.04 and Debian 12. It reads and writes every backup, record and share of 0.1.0, and its commands and questions stay the same apart from the changes below.

New in this version: `stitch`, or Embroidery in the menu's Encode, hides the phrase in a cross-stitch pattern made from your own picture, a PNG, JPEG or WebP. The phrase goes into the pattern's legend, masked with your dates unless you choose No Seedshift. With the Original Seedshift the pattern keeps every word but the last, so remember your phrase's real last word. The pattern is a PDF that looks like one bought from a designer, and Decode reads the phrase back from that PDF or from the legend typed in. [SeedStitch](https://github.com/hobby-eng/mnemocode/blob/v0.2.0/docs/SEEDSTITCH.md) explains how it works.

Cards can also carry a hidden QR record. A compatible ordinary scanner shows the contact or chosen text; MnemoCode reads the backup codes or share from the same QR image. The hidden QR record is not encrypted by this feature. [Hidden QR records](https://github.com/hobby-eng/mnemocode/blob/v0.2.0/docs/HIDDEN_QR.md) explains how to read it and what it protects.

What you will notice:

- Cards no longer need Poppler's `pdftocairo`.
- The menu explains each task and links to its section of the README.
- Secrets are wiped from memory when released, and small secret buffers ask the system to keep them out of swap. This is best effort: rendered pages and some working copies stay unlocked. A secret result is refused on a terminal without a private screen; files and pipes get it as before.
- Answers, files and standard input have limits, which `--help` names. A QR image may have up to 2 megapixels, enough for a 1920 × 1080 screenshot.
- Re-encode asks for the new backup before the old one.
- A new backup asks about Seedshift on one screen: MnemoCode Seedshift, Original Seedshift or No Seedshift.
- Every new backup asks the same questions in the same order, a cross-stitch pattern too: it can also save its legend as text and as a QR code and add the instructions for heirs.
- The menu no longer asks for each file's name. It asks once for the folder of all the files, by default the one MnemoCode was started in.
- A message about a saved file names it by its full path.
- A wallet check reads the coin from the address, so there is no coin to choose. `--bitcoin-profile` is gone: an address or a key names its own path.
- The npm package and the Node.js library are gone: the wallet-tools pages use this release's WebAssembly files.

PDF and PNG files have the same content as in 0.1.0, but different bytes. [CHANGELOG.md](https://github.com/hobby-eng/mnemocode/blob/v0.2.0/CHANGELOG.md) lists every change. The TypeScript version stays at [hobby-eng/mnemocode_typescript](https://github.com/hobby-eng/mnemocode_typescript) and gets fixes of critical defects only.

Check the download before you run it, as [Download verification](https://github.com/hobby-eng/mnemocode/blob/v0.2.0/docs/CLI.md#download-verification) explains.
