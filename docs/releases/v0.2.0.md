MnemoCode is rewritten in Rust: one executable that needs nothing else installed but glibc 2.35 or later on Linux, for Linux, macOS and Windows, and a WebAssembly file for each page of the wallet tools. It reads every backup, record and share of 0.1.0 and writes the same ones. Its commands, questions and messages are those of 0.1.0, apart from the changes below. The notes for those who develop MnemoCode are in [CHANGELOG.md](https://github.com/hobby-eng/mnemocode/blob/v0.2.0/CHANGELOG.md).

## What changes in use

- The README follows the menu order, with paired command examples and a documentation index. Each menu task and recovery choice shows its own explanation and a link to that section.
- Cards draw their PNG and JPEG images in the program: Poppler's `pdftocairo` is no longer needed, and no other program is started.
- Re-encode asks for the new backup before the old one, so that its outputs are ruled before any secret.
- On Linux with Landlock, a failed save may take another name only in the folders of its outputs.
- A command whose result is secret is refused on a terminal without a private screen. Files and pipes get the result as before.
- On Linux, a tracer attached to the process refuses secrets.
- Each answer, file and standard input has its own limit, which `--help` names, a BIP39 passphrase of 4 KiB among them; a longer one is refused with that limit. 0.1.0 read up to 1 MiB for each.
- A missing parent folder of an output file is made before the secret is read. Output paths are checked before a command's own options, so of a wrong path and a wrong option the path is named first, and a folder made for a refused command stays.
- A line of a secret result that 0.1.0 wrote to standard error goes to standard output where standard error is a terminal and no private screen is open.
- Text on cards is drawn without ligatures, so a text that only fit through a ligature may now be refused as too long. U+FFFF is refused as a character the card font lacks.
- The Protection line and the self-test no longer name "no other programs", since no program start is denied.
- A QR code image may have up to 2 megapixels, where 0.1.0 took 8: a screen of 1920 × 1080 fits, and the QR images that MnemoCode saves are 720 px; crop a larger photograph or page image to the code. A smaller image is read sooner; an image of noise can still take seconds, and Ctrl+C acts when the reading ends.
- A result that standard output does not take, as on a full disk, ends the command with exit code 1 and says so; a closed pipe, as with `| head`, ends it as done.
- The help of `--ask-secrets` says that standard error, too, must be the terminal, as its refusal does.
- Shares under a threshold of 1, which keep no SSKR digest, are refused as a set where they disagree: 0.1.0 named one of them as the share that does not fit, which their agreement does not prove. TS 0.1.1 does the same.
- A file name typed again after a file that could not be read, and the name of the next share's QR image, are read only from regular files: a named pipe without a writer is refused at once, where 0.1.0 waited for one and held Ctrl+C. TS 0.1.1 does the same.
- A word of a host's instructions for heirs wider than the page, such as a long subtitle without a space, is refused; 0.1.0 drew it off the page. TS 0.1.1 does the same.

## Same results, other bytes

- PDF files hold the same pages, text, positions and images; their bytes differ, since another writer makes them.
- PNG files other than page images have the same pixels. QR codes have the same payload, version and error-correction level, and their mask may differ.
- Page images have the same size, and the QR code of each page holds the same payload, read cropped to the code, with pixels within a small tolerance of 0.1.0's.

## Secrets

- Secrets live in types that wipe them, every freed block of memory is wiped, and the memory of a secret is kept out of swap where the system allows it. SECURITY.md names what is wiped but not locked: drawn pages, the codes on cards, a command's dates and a step's working copies.
- No secret stays in the memory of a page's WebAssembly file once an entry returns, and the gates check this on every commit.
- Random numbers come from the operating system, or in a browser from `crypto.getRandomValues`, and from nowhere else.

## No longer offered

- The npm package and the library for Node.js: pages take the WebAssembly files of this release.
- The Node.js permission model and the check of the SSKR engine's files at start: the engine is linked into the program.

## Distribution

- Each release has one executable file for Linux on x86-64 and ARM64, Windows on x86-64, and macOS on ARM64 and x86-64, and an archive of the WebAssembly files for each page. The Linux executables need glibc 2.35 or later, which Ubuntu 22.04, Debian 12 and newer systems have; musl systems such as Alpine cannot run them.
- The Linux and Windows executables and the WebAssembly files are built twice in a pinned container, and a byte that differs stops the release. macOS executables are built on macOS runners, as Apple's SDK needs, and are checked but not rebuilt byte for byte.
- GitHub signs the build provenance of every release file, and the `SHA256SUMS` of every release is signed with the maintainer's OpenPGP key; [Releasing](https://github.com/hobby-eng/mnemocode/blob/v0.2.0/docs/RELEASING.md) describes the steps.
